# Windows SMTC и внешний Windhawk

## Что установлено по приложенному исходнику

Исследован `Island Media Controls 0.10.55`. `SelectBestSession` получает `manager.GetSessions()`: выбирает текущую играющую, затем первую играющую, иначе current/first. Фильтра, запрещающего Pulse, в этой функции нет. Кнопка play/pause вызывает `TryTogglePlayPauseAsync`; seek — `TryChangePlaybackPositionAsync`.

Поэтому переименование Pulse.exe, наличие C++-файла мода в app.asar или `setAppUserModelId` сами по себе не создают медиасессию. До этого Pulse зависел от публикации Chromium, в том числе из YouTube iframe. Причина конкретного случая «не видит» без Windows session dump остаётся не подтверждённой.

## Исправление 1.0.0

Добавлен независимый Windows SMTC publisher. `Windows.Media.Playback.MediaPlayer` используется только как владелец `SystemMediaTransportControls`; `CommandManager.IsEnabled=false`. Контент и звук остаются в существующем Electron-плеере. Никакого silent audio, второго декодера, глобального перехвата Explorer или старого островка.

Главный процесс передаёт ограниченное состояние через stdin своему дочернему процессу; команды возвращаются по stdout по allowlist. Play/Pause идемпотентны, seek принимает секунды и ограничивается длительностью. Неизвестные команды, нечисловая позиция и слишком длинные ответы отклоняются. При backpressure сохраняется только последнее состояние. При закрытии Pulse stdin завершается, SMTC выключается; аварийный перезапуск ограничен тремя попытками. Пока мост активен, глобальные MediaPlayPause/Next/Previous отключены во избежание двойной обработки. Chromium Media Session не удалена — это fallback для платформ без моста.

AUMID — `com.scada.pulse`; Windows может отображать executable identity отдельного helper `PulseMediaBridge.exe`, а не строку «Pulse» как имя источника. Проверять нужно также title/artist, а не только подстроку в source ID. Не стоит патчить Windhawk фильтром только на Pulse: это сломает его работу с другими плеерами.

Лог состояния: `%APPDATA%/pulse-player/media-session.log` (либо `media-session.log` в каталоге профиля Electron). Записываются только запуск/готовность/ошибки протокола; названия треков, cookies и токены не пишутся. Есть ограничение размера 256 КиБ с одной предыдущей копией.

## Обязательная проверка на Windows 10 2004+ / Windows 11

1. Полностью закрыть прежний Pulse и другие играющие приложения. Запустить новый, включить трек. В логе должен появиться `ready`.
2. Проверить трек в системных медиаконтролах Windows и затем в Windhawk. Нативный мост начинает публиковать активную сессию после появления трека, а не пустого окна.
3. Проверить офлайн/audio и встроенный YouTube отдельно: Play → повторный Play не ставит на паузу; Pause → повторный Pause не запускает; Next/Previous переключают один раз.
4. Перемотать в моде, проверить фактическую позицию и обратное обновление прогресса; сменить трек и обложку.
5. Свернуть/закрыть в трей: управление продолжает работать. «Выход» должен убрать сессию и helper. Перезапустить приложение.
6. Запустить музыку в браузере одновременно: мод вправе выбрать текущий играющий браузер. Это его алгоритм выбора, не доказательство, что Pulse отсутствует в GetSessions.
7. Если `ready` есть, а сессии нет — сохранить версию Windows, движок audio/iframe и GSMTC session dump. Если сессия есть и системные кнопки работают, а мод не показывает её — проверять кэш/выбор сессии мода.

## Границы проверки этого выпуска

Мост скомпилирован против Windows SDK; протокол и интеграция проверены автоматическими тестами. Реальный WinRT runtime, появление GSMTC-сессии, аппаратные клавиши и Windhawk на Windows в Linux-среде не запускались. Поэтому это реализованное исправление архитектурного пробела, а не подтверждённая end-to-end совместимость.

### Снять список сессий

В **Windows PowerShell 5.1** можно выполнить включённый read-only скрипт `tools/diagnose-media.ps1` из папки исходников. Он не меняет систему и не требует администратора. Не ослабляйте политику выполнения ради него: если запуск заблокирован, можно просмотреть и выполнить его содержимое в консоли вручную. Вывод содержит названия/исполнителей текущих треков — проверьте его перед публикацией. Скрипт в Linux не исполнялся.

Ручная интеграция следует Microsoft: [Manual control of the System Media Transport Controls](https://learn.microsoft.com/en-us/windows/uwp/audio-video-camera/system-media-transport-controls) — получение `MediaPlayer.SystemMediaTransportControls`, отключение `CommandManager`, собственные обработчики и обновление состояния/метаданных. Это подтверждает способ использования API, а не заменяет проверку Windows runtime.
