# Публикация Pulse на GitHub

## Исходники

В репозитории должны лежать распакованные исходники из нового архива: папки `app/`, `docs/`, `scripts/`, `.github/` и несколько корневых файлов, включая README.md, LICENSE, AGENTS.md, package.json и package-lock.json.

Используйте GitHub Desktop / Git: некоторые включённые медиаинструменты превышают лимит веб-загрузчика на один файл. Содержимое архива копируется в папку клонированного репозитория; ZIP не заменяет историю исходников. При переходе со старой раскладки удалите старые файлы проекта, сохранив `.git`: [пошагово](REPOSITORY-LAYOUT.md).

Не загружайте node_modules, app/dist, пользовательские профили, cookies, скачанную музыку и личные ключи. Проектный ключ Spicy уже встроен с ранее зафиксированного разрешения автора и будет публичным при распространении; [подробности](history/SPICY-PROJECT-1.0.0.md).

## GitHub Actions

Workflow **Build Windows artifacts** находится в `.github/workflows/build.yml`. Он работает из `app/`, использует `app/package-lock.json` для npm cache и собирает `app/dist/*.exe`.

Запуск — Actions → Build Windows artifacts → Run workflow или push тега вида v*. Это создание артефакта, не автоматическая публикация GitHub Release. Нативная установка и работа на Windows в этом Linux-job не проверяются.

## Releases

Для выпуска 1.0.0 прикрепите:

- Pulse-Setup-1.0.0.exe;
- Pulse-1.0.0-portable.exe;
- SHA256SUMS.txt от соответствующей сборки.

Используйте последние ранее подготовленные EXE с исправлением перетаскивания виджета. Одна только переорганизация исходников не меняет их поведение. Не перезаписывайте существующий тег вслепую; пересборки с той же версией различайте описанием и SHA-256.

Проверьте приложение на Windows перед публичным релизом. Установщик и portable не подписаны сертификатом.
