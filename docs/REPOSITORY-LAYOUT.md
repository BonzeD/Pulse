# Структура исходников Pulse 1.0.0

## Что перенесено

- Код приложения, renderer, build, native, resources, tests, tools и исходные package.json/package-lock.json — в `app/`.
- Исторические Markdown-отчёты — в `docs/history/` без изменения содержимого.
- Оформление и Immersion — в `docs/guides/`.
- Правила FOR AI и исходные задания — в `docs/development/`.
- Прежние манифесты — в `docs/manifests/`. Их пути относятся к прежней раскладке; это история, а не актуальная проверка нового дерева.
- Полный README предыдущего архива сохранён как `docs/history/README-before-reorganization.md`; в корне — новый краткий README.

Точные соответствия прежних и новых путей находятся в `docs/manifests/REORGANIZATION-MAP.json`. Внутренние runtime-пути приложения и содержимое runtime-файлов сохранены. NOTICE, PLUGINS и копия LICENSE остаются внутри app/, потому что их использует упаковка Electron.

## Команды

Из корня:

```sh
npm ci
npm test
npm start
npm run build:media
npm run dist
```

Корневой package.json — обёртка. npm ci ставит зависимости в app/node_modules, сборки появляются в app/dist. Те же команды доступны напрямую после `cd app`.

Полная Windows-сборка через исходные shell-скрипты рассчитана на Linux/WSL/GitHub Actions. Архив исходников можно создать командой `npm run source` (нужен Python 3). Архив включает весь репозиторий, .github и вложенный Python runtime yt-dlp, но исключает зависимости npm, результаты сборки, временные файлы и .env.

## Как заменить прежние исходники в GitHub Desktop

1. Сохранить резервную копию текущей рабочей папки вне репозитория, если в ней есть свои незакоммиченные изменения.
2. В GitHub Desktop открыть `Repository → Show in Explorer` и убедиться, что это папка нужного Pulse-репозитория.
3. Удалить **старые файлы проекта и его папки**, но **не удалять скрытую папку `.git`**. Если `.git` не видно — включить отображение скрытых элементов в Проводнике. Не трогать файлы за пределами этой рабочей папки.
4. Скопировать **содержимое** папки Pulse-1.0.0 из нового архива в папку репозитория. Не переносить внешний ZIP и не создавать лишний уровень Pulse-1.0.0/Pulse-1.0.0.
5. В GitHub Desktop просмотреть изменения: переносы могут отображаться как удаление старых и добавление новых файлов — это нормально. Проверить, что .github/workflows/build.yml присутствует.
6. Summary: `Organize Pulse source and documentation into folders`.
7. Нажать Commit to main, затем Push origin.

Простое копирование поверх старого дерева **не удаляет прежние корневые файлы** — в этом случае длинный список останется. .git сохраняет связь с репозиторием и историю коммитов; новый репозиторий создавать не нужно.

Для загрузки исходников через GitHub Desktop запускать npm ci не требуется. Не коммитить node_modules, dist, профили, cookies, скачанные медиа или личные ключи.

## Проверка и ограничения

`npm test` запускает прежние тесты приложения и дополнительную проверку структуры. `npm run test:structure` проверяет наличие новых путей, версии и неизменность перенесённых файлов по карте переноса.

Эта доработка изменяет структуру исходников и служебные пути, а не поведение программы. Ранее собранные EXE не нужно пересобирать только ради расположения исходных файлов в GitHub. Новый Windows-билд в этом архиве не заявляется; нативные Windows-проверки по-прежнему обязательны перед выпуском.
