# Pulse 1.0.1 — аудит клиента и разбор Windhawk

## Результат и границы

Основа — предоставленный Pulse 1.0.0 panel17. Экспериментальный file-only патч native Liquid Glass в эту сборку не переносился.
Удалён именно новый островок над системным треем, а не старый отдельный desktop-виджет.

Проведены обзор кода основных процессов и мостов, проверка локального HTTP/офлайн-выдачи, сохранения данных, асинхронных переходов плеера, Media Session, разрешений, окон входа, состава пакета и зависимостей. Выполнены автоматические проверки и выборочная визуальная проверка снимков интерфейса.
Это инженерный аудит в доступном Linux-окружении, не независимый penetration test и не доказательство отсутствия всех ошибок. Приложение Windows и реальный Windhawk/Explorer здесь запустить нельзя. Платные сервисы, живой вход в аккаунты и нестабильность YouTube не выдаются за проверенные.

## Подтверждённые проблемы и исправления

### A01. Выход за каталог локальной раздачи — высокий приоритет

Было: `startsWith(root)` принимал соседние каталоги с общим префиксом, например `renderer-private` и `plugins-private`. В plugin-маршруте происходило повторное URL-декодирование. URIError от некорректного percent-encoding не перехватывался в HTTP callback.

Стало: однократное декодирование с ответом 400; проверка через `path.relative`, запрет Windows-разделителей/двоеточия/NUL; проверка realpath и обычного файла; ссылки за пределы каталога не выдаются. Проверяются Host, cross-site Fetch Metadata и допустимый метод. Перебор занятого порта ограничен, другие ошибки старта не превращаются в бесконечную рекурсию.

Проверка: `tests/audit.cjs` — sibling-prefix, traversal, symlink, malformed URL, неизвестный Host, double-encoded plugin path; реальный HTTP-сервер продолжает отвечать после невалидного запроса.
Ограничение: это не изоляция от вредоносной программы, уже запущенной под тем же Windows-пользователем. Локальные плагины по-прежнему являются доверенным кодом пользователя, не устанавливайте неизвестные JS-файлы.

### A02. Невалидные диапазоны офлайн-аудио — высокий приоритет надёжности

Было: перевёрнутые/запредельные Range могли приводить к ошибке потока; `bytes=-3` ошибочно означал начало файла; ошибки read stream не обрабатывались. Каталог не отличался от обычного файла.

Стало: строгий single-range parser, корректный suffix/open-ended range, ограничение конца размером файла; 416 + `Content-Range: bytes */size` для невалидного диапазона; HEAD без тела, обработка ошибок/закрытия потока. Та же строгая проверка путей применяется к офлайн-файлам. Ошибка upstream-потока больше не проглатывается с незавершённым ответом; неиспользуемое тело 403/410 отменяется перед повтором.

Проверка: parser boundary cases, overflow, multipart, empty file, реальная HTTP-выдача суффикса/416/HEAD и запрет соседнего каталога.

### A03. Привилегированный IPC и навигация — высокий приоритет

Было: основные IPC handlers не проверяли identity/origin отправителя. Привилегированные окна могли уйти на внешний документ, сохранив preload. Permission handler выдавал практически все запрошенные разрешения.

Стало: точная проверка известного WebContents, main frame, схемы/хоста/порта/пути. Библиотека, reset и аккаунты доступны только главному окну. Виджету разрешены только его команды и открытие/скрытие/редактирование виджета. Обоям — только ограниченный wall:act. Навигация/redirect главного окна, виджета и обоев ограничена собственной страницей, popup не создаёт привилегированное окно. В основной сессии разрешения запрещены по умолчанию, кроме допустимого fullscreen основного окна. Камера/микрофон/геолокация не выдаются автоматически этим handler.

Проверка: unit-отказы для дочернего frame, чужого origin/отправителя и привилегированного вызова от виджета; интеграционный запуск настоящего Electron с реальным preload/IPC. Окна авторизации сервисов остаются отдельными sandboxed partition-окнами без основного preload; полный живой login не проверен.

### A04. Риск потери библиотеки и последних изменений — высокий приоритет данных

Было: запись JSON с непосредственным усечением live-файла; повреждённый JSON читался как пустой store. Последние изменения до истечения debounce 400 мс могли не успеть сохраниться при выходе.

Стало: запись во временный файл в том же каталоге, fsync файла и rename. Для library.json поддерживается предыдущий корректный `.bak`, при повреждении primary читается backup. Последний pending save сбрасывается синхронным ограниченным IPC на beforeunload. Обычный relaunch использует штатный quit; intentional factory reset не сохраняет старые настройки обратно. После сброса настроек старый backup удаляется. Аккаунты/кэш сервисов тоже пишутся атомарно, но для cookies не создаются дополнительные backup-копии удалённых аккаунтов.

Проверка: восстановление повреждённого primary, имитация отказа rename без усечения live-файла и уборка temp, отсутствие backup для credential snapshots; реальное сохранение и unload flush через Electron.
Ограничения: backup хранит предыдущую, а не обязательно последнюю версию. Это не бесконечная история и не абсолютная гарантия при повреждении диска/одновременной порче обоих файлов. Системный сбой/kill не даёт beforeunload, поэтому debounce-окно при таком сбое полностью не устраняется. Не копируйте cookie-файлы в публичные отчёты. Резервные копии важной библиотеки всё равно нужны.

### A05. Неверная семантика системных Play/Pause — воспроизведено

Было: обе Media Session actions вызывали `toggle`. Уже играющий трек мог остановиться от Play; пауза могла включить остановленный трек. playbackState явно не обновлялся; после очистки очереди могли оставаться старые metadata.

Стало: Play запускает только при необходимости, Pause только останавливает; playbackState синхронизируется со статусом, пустая очередь очищает metadata. Добавлен seekto с проверкой конечного числа и границ.

Проверка: старый дефект воспроизводится тестом; новые repeated Play/Pause идемпотентны. Это исправляет ошибку клиента, но само по себе не гарантирует появление GSMTC-сессии на любой Windows.

### A06. Запоздалые callbacks от предыдущего трека — подтверждено в коде

Было: timeout автопропуска и loadedmetadata listener могли сработать после ручного выбора другого трека; отклонённый resolve IPC не обрабатывался. Отказ audio.play мог оставлять спиннер.

Стало: callbacks сверяют generation token; resolver rejection превращается в обычный обработанный результат, отказ play убирает loading только для актуального поколения. Основной resolver, iframe fallback, очередь и алгоритмы GPU/визуализации не заменялись экспериментальными реализациями.

Проверка: точное сравнение playback с историческим snapshot, к которому применены только перечисленные allowlisted replacements; отдельные behavioral checks. Исторические SHA baseline сохранены, не «обновлены ради зелёных тестов».

### A07. Устаревший Electron — известные уязвимости

Исходный 37.10.3 отмечался npm audit как High, в том числе для изоляции/разрешений/навигации. Обновлён до стабильного 44.8.0. Применён совместимый `npm audit fix`, без принудительного downgrade electron-builder.

После обновления: 0 Critical, 0 High, 8 Moderate в дереве инструментов сборки (electron-builder → старый @electron/get/global-agent/roarr/sprintf-js). `npm audit --omit=dev` — 0, но Electron хоть и указан devDependency, фактически входит в бинарный выпуск, поэтому его обновление обязательно и выполнено. Нулевой omit=dev сам по себе НЕ доказывает безопасность Electron/Chromium.

Оставшиеся Moderate не названы устранёнными. Автоматическая рекомендация npm сводилась к изменению major/понижению builder до 26.5.0, это не применялось вслепую. Сборку следует делать в изолированной среде и не подставлять произвольные format-строки. Raw audit JSON приложен в audit-evidence.

### A08. Удаление посторонних файлов при uninstall — высокий приоритет данных

Было: `RMDir /r "$INSTDIR"` рекурсивно удалял всё содержимое произвольной папки, выбранной при установке. Если установить Pulse в папку с другими файлами, uninstall удалял и их.

Стало: на этапе сборки генерируется `build/uninstall-files.nsh` со списком файлов, реально принадлежащих пакету. Удаляются только эти пути и собственный uninstaller; каталоги удаляются только если пусты, без `/r`. Посторонние файлы оставляют каталог на месте. UI выбора пути нормализует его и запрещает корень диска и очевидные личные/системные каталоги. Это не отменяет риски ручного `/D=` override или установки поверх совпадающих имён — выбирайте отдельную папку Pulse.

Проверка: manifest unit test с обычным файлом и вложенным app.asar; отсутствие recursive delete INSTDIR, порядок file-before-directory, проверка фактического manifest. Установка/удаление на Windows здесь не запускались. Установщик всё ещё умеет принудительно закрывать Pulse по имени процесса: сначала завершите его через «Выход», чтобы не потерять последние несохранённые изменения.

### A09. Повреждённый Discord IPC frame мог повесить главный процесс

Было: длина сообщения читалась как signed int32 без проверки. При `len=-8` вычисление `buf.slice(8+len)` не сдвигало буфер и parser крутился бесконечно; чрезмерный размер мог удерживать растущий буфер. Это локальный IPC доверенного Discord, не удалённый сетевой exploit, но ошибка способна заморозить весь клиент при некорректном ответе.

Стало: отрицательные/слишком большие frames закрывают соединение с контролируемым статусом/повтором; максимальный frame — 1 МиБ, суммарный входной буфер — 2 МиБ. Обычный формат Discord не менялся.

Проверка: VM timeout reproducer исходного parser и regression test для отрицательных и чрезмерных длин; новый parser возвращается без зависания. Реальный Discord RPC на Windows не проверен.

## Почему Windhawk не видел / плохо управлял Pulse

Разбор именно предоставленного `Island Media Controls 0.10.55`:

1. В исходнике `@include explorer.exe` (строка 9). Это Windhawk-мод для Explorer, не Node/Electron-модуль. Само наличие `.wh.cpp` внутри app.asar не компилирует, не загружает и не подключает его к Pulse. Удалённый Electron-островок был отдельным интерфейсом, вызывавшим private IPC Pulse, а не настоящим портом GSMTC-механизма.
2. `SelectBestSession` (строки 2324–2365 исходника) перечисляет системные сессии. Предпочтение — текущей играющей, затем первой играющей, иначе current/first. Это НЕ поиск по `com.scada.pulse`. Поэтому играющий браузер/другой плеер может выиграть у паузы Pulse.
3. Кнопка мода вызывает `TryTogglePlayPauseAsync` (например строки 7134–7137), next/prev — соответствующие GSMTC TrySkip. Она не знает про `pulse.command` и не может управлять несуществующей системной сессией. Неверно было бы утверждать, что этот исходник напрямую вызывает TryPlayAsync/TryPauseAsync: в проверенном обработчике используется именно Toggle.
4. У Pulse уже был `app.setAppUserModelId('com.scada.pulse')`. Проблема НЕ сводится к отсутствующему AUMID. Media Session реализована через Chromium, отдельного собственного native GSMTC publisher в клиенте нет. Chromium/Windows публикует доступную медиасессию по состоянию реального media playback; просто запущенный клиент без трека — не обещание активной сессии. Поведение embedded YouTube и выбор активной сессии также требуют проверки на Windows.
5. Подтверждённая ошибка Pulse с Play/Pause и отсутствием явного playbackState исправлена (A05). Она способна нарушать управление системными контроллерами, но без live GSMTC trace нельзя честно назвать её единственной причиной конкретного сбоя Windhawk.
6. Нет доказательства, что Pulse специально «заблокирован» фильтром мода: список известных native music sources не содержит Pulse, но отсутствие в этом списке само по себе не означает исключение из GetSessions.

Итого: исправлена реальная ошибка клиента, но полная совместимость внешнего Windhawk НЕ объявляется достигнутой. Мод и его порт удалены из нового выпуска по запросу, собственный native bridge не добавлялся. Для оставшегося внешнего мода проверка такая: запустить уже выбранный трек в Pulse, временно остановить другие источники, проверить Pulse в системном медиаконтроле Windows; затем сравнить с выбором сессии Windhawk. Если Pulse не появляется даже там — нужен GSMTC session dump с реальной Windows и отдельная проверка Chromium/iframe; если там работает, а в моде нет — исследовать выбор/кэш сессии самого мода.

Контрольная сумма удалённого исходника зафиксирована в `audit-evidence/windhawk-origin.sha256`; сам сторонний C++-мод больше не поставляется в клиенте.

## Что удалено / что сохранено

Удалены tray-island.js, island-preload.js, renderer/tray-island.*, renderer/tray-settings.js, port-only переводы и CSS, загрузка createIsland, vendor/island-media-controls, build entries и старые tests/tray-island*. Старые исторические CHANGES остаются историей. Инертные настройки `settings.island` в существующем профиле не удаляются с риском повредить библиотеку; новый клиент их не использует. Убран несуществовавший и неиспользуемый lyralign.js из build.files.

Сохранены оригинальный desktop-виджет (renderer/widget.*), обычное меню трея, каталоги сервисов, аккаунты, очередь, тексты, MineRadio, GPL и атрибуция оставшегося стороннего кода. about-legal обновлён под фактический NOTICE, без удалённого порта.

## Установка и воспроизведение

Закрыть старый Pulse полностью через «Выход» в обычном трее. Установить Pulse-Setup-1.0.1.exe в тот же каталог либо запустить portable. Перед обновлением сохранить копию пользовательской библиотеки; эта версия намеренно не сбрасывает профиль и не удаляет скачанные треки. Не удалять профиль для удаления островка: код его больше не создаёт.

Для сборки исходников: Node 24, `npm ci`, `npm test`, `npm run dist`. Electron 44 использует явный installer; root postinstall вызывает его. Нужны сеть для официальных артефактов и Chromium для генерации installer UI. На Linux runtime-тест дополнительно требует GTK3, Xvfb и `npm run test:electron`; production Windows-приложение не запускается с тестовым `--no-sandbox`.
