# Audius integration — Pulse 1.0.2

Версия сохранена: **1.0.2**. Это обновлённые исходники, не Windows-сборка. GitHub/release не публиковались. Исходный установщик и прежние графические исправления сохранены.

## Что реализовано

- Четвёртая платформа `ad` в общем переключателе; публичный поиск треков, исполнителей и плейлистов, страницы исполнителя/плейлиста, weekly trending tracks/playlists через официальный API.
- Нативные Audius ID имеют namespace `ad:`. Прямой поток `/tracks/{id}/stream` проходит через loopback proxy Pulse в тот же HTMLAudioElement и AudioContext. YouTube для Audius-каталога не используется.
- Очередь, повтор, shuffle, общий транспорт, скорость/громкость/перемотка, визуализаторы и существующая шина состояния остаются общими. Локальные плейлисты и лайки не требуют входа в Audius; лайки не уходят в YouTube queue.
- Источник воспроизведения хранится отдельно от ID исходного трека. Ручное соответствие хранит только ID записи, не временный stream URL. В плеере есть индикатор источника, окно выбора, ссылка на запись, возврат к прежнему источнику и сброс соответствия.
- Безопасное значение по умолчанию — **Текущий источник**. Для native `ad:` даже оно означает прямой Audius.
- **Автоматически**: только уже подготовленное уверенное соответствие из session cache; Play не запускает новый поиск. **Предпочитать Audius**: допускается ограниченный запрос перед Play; при отсутствии совпадения или ошибке работает прежний путь.
- Фоновый подбор: один worker, ближайшие два трека очереди, только метаданные. Запросы отменяются при смене трека/настройки, дедлайн select 2.5 s; общий fallback startup timer для альтернативы 3.5 s, для native Audius 8 s. После `playing` источник не меняется автоматически.
- Сопоставление консервативное: нормализованные точные название/исполнитель, длительность в пределах min(2 s, 1%), версии и parental warning, ISRC при наличии. Неизвестные explicit flags требуют одинакового ISRC. Remixes/covers, конфликты ISRC, версии и неоднозначные дубликаты отвергаются. Это не аудиофингерпринтинг и не гарантия идентичности аудиофайлов.
- Пользовательский текст/выбор, offset/stretch и черновики редактора запрещают альтернативный источник. Неподтверждённый ручной выбор очищает текущее отображение старого текста, но не сохранённые данные. Редактор для альтернативной записи требует вернуть исходный источник. Native Audius использует собственный `ad:` ключ коррекций.
- Gated/restricted/unavailable tracks отфильтрованы. Скачивание и whole-file autosync analysis для Audius отключены; live analyser доступен. Полнофайловый анализ не используется для подбора.
- RU/EN/JA/UK, исходные названия и имена не переводятся. Узкое окно получает компактную навигацию CSS без изменения `lib.mini`. Существующая библиотека иконок; самодельный знак Audius не добавлялся.

## API, условия и безопасность

Проверены официальные ресурсы:

- API reference: https://api.audius.co/v1 и https://docs.audius.co/llms-full.txt
- API Terms: https://audius.co/documents/ApiTerms.pdf
- Open Music License: https://audius.org/open-music-license.pdf
- Terms update: https://blog.audius.co/posts/audius-terms-of-service-update

Используются только публичные API endpoints. В проверенной среде они работали без developer secret и без аккаунта; это не гарантия неизменности доступа/лимитов. Подписи для gated tracks не генерируются, ограничения создателя не обходятся.

Metadata TTL 60 s, bounded process-memory cache. На диск сохраняются пользовательские ссылки-ID и настройки/тайминги, не полученные от Audius названия/исполнители/обложки/ISRC. При следующей сессии metadata заново запрашиваются онлайн. Это означает отсутствие Audius-метаданных офлайн. Аудио не пишется на диск, proxy — `Cache-Control: no-store`; signed stream addresses не сохраняются. Следует повторно проверить текущие условия до публичного распространения/монетизации, особенно если планируется persistent media cache или downloads. Это техническая интеграция, не юридическое заключение.

Ограничены частота metadata requests (~5/sec), размер ответов и artwork, очередь запросов; 429 останавливает также уже ожидающие metadata-запросы. HTTPS redirects проверяются на каждом шаге, DNS адреса закрепляются и не могут вести в private/local сети. Секретов в клиент не добавлено. Защиты loopback Host/origin и существующие IPC сохранены.

## Как включить

1. Установить зависимости из корня `npm ci`; запустить `npm start` на поддерживаемой системе.
2. В переключателе платформ нажать четвёртую кнопку с нотой — Audius. Вход не нужен.
3. Найти трек или открыть популярную подборку и нажать Play.
4. Для альтернативного аудио: **Настройки → Клиент → Audius → Источник звука**. По умолчанию всё остаётся на прежнем источнике.
5. В кнопке источника над транспортом можно выбрать запись вручную, открыть оригинал, вернуть текущий источник или сбросить сохранённое соответствие. Сброс удаляет ручное соответствие; включённый автоматический режим позже может найти совпадение вновь.

## Оставшиеся ограничения

- Вход/облачная библиотека Audius, лайки/подписки аккаунта, uploads, paid/gated content, downloads/offline Audius не реализованы и не выдаются за доступные функции.
- Первая страница исполнителя/плейлиста ограничена 100 треками; нет UI пагинации. Search — до 30 треков, 15 исполнителей, 20 плейлистов; Home показывает до 16 элементов каждой полки. Это не полный экспорт каталога.
- Консервативный matcher часто откажется от альтернативы, особенно при неполных ISRC/explicit метаданных существующей платформы. Успешный настоящий cross-platform match на одном и том же наборе записей в этой среде не подтверждён.
- Для альтернативной записи ручные тайминги не мигрируются. Whole-file auto word sync Audius отключён; обычные текст/редактор/пословные модели остаются прежними. Текст доступен только если его вернёт существующий провайдер или добавит пользователь.
- Mini-widget/SMTC используют прежнюю шину; DOM/unit проверки не заменяют нативные Windows-тесты. Реальное Windows hit-testing, системные медиакнопки, installer/update и GPU FPS нужно проверить на Windows. Windows-сборка не выполнялась.
- API/сеть/каталог зависят от региона и сервиса. Нет обещания ускорения или доступности любой записи.

## Проверки

Результаты и сырой замер: `audius-1.0.2/`. Команды из `app/`:

```sh
npm test
npm run test:audius
CHROMIUM_PATH=/path/to/chromium npm run test:audius-live
npm run test:final-ui
npm run test:final-effects
npm run test:graphics-102
npm run test:panels-102
npm run test:lyric-studio
npm run test:widget-clicks
npm run test:file-video
```

`test:audius-live` использует настоящую сеть Audius, loopback proxy и renderer, но stub preload/IPC. Это не полный Electron/Windows E2E. Замер — от запуска `setQueue/Play` до первого ненулевого сигнала Web Audio analyser; физический выход динамиков и задержка Windows audio stack не измерены. Первый Play выполняется после загрузки Home (часть metadata уже тёплая), повторный — в том же процессе. Оба числа — одиночные наблюдения, не статистика производительности.

Сравнение «прежний путь против Audius на одинаковых записях», включая cold/warm и реальные fallback-to-YouTube, **не завершено**. В API Terms также есть запрет на benchmarking/competitive use: отдельный сравнительный бенчмарк не следует проводить без уточнения разрешения Audius. Ниже сохранён только уже сделанный технический smoke test появления аудиосигнала, без сравнительного вывода о платформах. Пробный запрос к YouTube player вернул `ERROR`, «Видео недоступно», без audio formats. Это только reachability probe, а не matched-track benchmark и не доказательство глобальной недоступности YouTube. Таймауты/fallback/races проверены отдельно контролируемыми тестами, не выдаются за сетевые замеры.

Исторические hashes и baseline-файлы не перезаписаны. `tests/audius-approved.json`/`audius-original.cjs` — отдельный точный обратный diff для совместного запуска прежних baseline tests; новые функции проверяются без обратных патчей в `audius.cjs`, `audius-runtime.cjs`, `audius-ui.cjs`.
