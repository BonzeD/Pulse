# EmbeddedFirst — порядок воспроизведения

## Что изменено

- Онлайн-треки YouTube и сопоставленные треки сервисов сначала передаются встроенному YouTube IFrame Player.
- Для треков сервисов выделен IPC `yt:map`: он ищет только YouTube video ID и не извлекает прямую ссылку на аудио.
- Ошибка встроенного плеера, блокировка автозапуска или отсутствие готовности/старта переводят текущую загрузку в существующий прямой resolver с резервным yt-dlp. Таймаут — 10 секунд на ожидание готовности/сопоставления, затем 10 секунд на старт/буферизацию плеера; это не обещание общего запуска за 10 секунд.
- Если загрузка iframe API уже завершилась ошибкой, сразу используется резервный путь.
- Отложенное разрешение адреса не может заменить более новый трек. Пауза и перемотка сохраняются при переходе на резервный поток. После ошибки резервный поток не возвращается автоматически в уже отказавший iframe.
- Автоматическая подготовка прямых потоков при наведении и переходе к следующему треку отключена. Нативный IPC prefetch оставляет только отмену старой задачи. AutoSync не скачивает онлайн-трек для анализа во время встроенного YouTube.
- Локальные/скачанные файлы остаются в файловом плеере; собственное воспроизведение Audius не заменяется YouTube.
- Изменение режима обложка/видео/визуализация само по себе не перезапускает работающий встроенный плеер.
- Сохранены исправления ReliabilityFix, расширенная диагностика и нативное копирование аудиолога.

## Ограничения

Встроенный YouTube воспроизводит звук отдельно от обычных аудиодек Pulse: EQ, DJ-сведение и эффекты основной Web Audio-цепочки не обрабатывают его. Автоматический полнофайловый анализ AutoSync для такого онлайн-воспроизведения не запускается. Это не отключает обычные тексты песен или обработку локальных/скачанных файлов. Доступность конкретного ролика по-прежнему зависит от YouTube, региона, сети и разрешения на встраивание; успешное воспроизведение каждого трека не гарантируется.

## Проверка

- Полный `npm test`: 593 теста; 592 успешно, 0 ошибок, 1 пропущен.
- 25 новых сценариев EmbeddedFirst: встроенный плеер первым, отложенная готовность, отдельное сопоставление сервисов, таймауты, error 150, сохранение паузы/позиции, быстрые переключения, поздние ответы и события, локальные файлы, запрет фонового извлечения и нативный IPC.
- Full-renderer UI: имитация YouTube API, реальные кнопки интерфейса, пауза в ожидании сопоставления, визуальные режимы, переход на резерв и изоляция запоздалого ответа.
- Остальные UI-регрессии: audio-engine, background/developer (включая копирование/сохранение лога), direct-stream, session-stream, adaptive-stream, startup-latency, reliability. Локальные HTTP/WAV и имитация subprocess; там, где проверяется аудио, использован настоящий декодер Chromium/AudioContext.
- Старые direct-first контракты сохранены как исторические контроли через точные обратимые тестовые патчи; текущий EmbeddedFirst отдельно исполняется в новых unit/UI тестах. Тестовые инверсии не импортируются приложением.
- Это Linux-стенды, НЕ нативный запуск Windows и НЕ замеры реального YouTube. Задержка на компьютере пользователя не измерялась.

## Сборка и диагностика

Собирать только portable:

```sh
cd app
./node_modules/.bin/electron-builder --win portable --x64 --publish never
```

`npm run dist` в историческом проекте также вызывает генерацию setup, поэтому для portable-only его не использовать.

Готовый файл: `Pulse-1.0.3-EmbeddedFirst-portable.exe`, Windows x64, без цифровой подписи. Установщик не создавался. Данные профиля/библиотеки не очищаются, способ хранения профиля остаётся прежним.

В аудиологе поле `build` должно быть `EmbeddedFirst-AudioDiagnostics2`. Добавлены событие `engine-policy` и причины перехода `embedded-ready-timeout`, `embedded-start-timeout`, `embedded-error`, `embedded-autoplay-blocked`, `mapping-error`. В лог не добавляются названия треков, URL, cookies или сырые сообщения об ошибках.
