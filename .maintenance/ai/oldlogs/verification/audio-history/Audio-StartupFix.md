# Pulse 1.0.3 — Audio Startup Fix

Основа: `Pulse-1.0.3-AdaptiveAudio-source.zip` (первая, экспериментальная версия).
Вторая версия AudioBackground не изменена. Это исправленные **исходники**, не готовый Windows EXE.

## Изменения

Изменена логика только в `app/offline.js` и `app/stream-race.js`:

- Прямые клиенты YouTube сохраняют приоритет, но получают фору 1500 мс. Если они ещё не нашли проверенный поток, параллельно запускается существующий резервный `yt-dlp`.
- Если прямые клиенты уже отказали, резервный путь начинается сразу, без ожидания таймера.
- Побеждает первый **проверенный реальными аудиоданными** поток. Один ответ API с URL не считается успешным результатом.
- Ошибка резервного пути не отменяет прямые запросы, пока у них остаётся возможность получить рабочий поток.
- При выборе победителя проигравшие запросы отменяются; если проиграл уже запущенный резервный subprocess, ему отправляется завершение.
- Отмена подготовки следующего трека и смена сессии теперь передаются также в гонку прямых клиентов, а не только в резервный процесс.
- Наведение мыши остаётся лёгким: оно не запускает резервный процесс. При клике уже выполняющийся запрос повышается до активного без повторного поиска. Если его 1500 мс уже истекли, резерв подключается сразу.

Правила проверки реального диапазона аудио, выбора качества, авторизации, хранения пользовательской библиотеки и условной предзагрузки следующего трека сохранены. Интерфейс и настройки не изменены. Новых зависимостей для приложения нет. Версия и идентификатор приложения сохранены.

## Проверка

- Полный `npm test` из `app/`: **536 тестов; 535 прошли, 0 ошибок, 1 пропущен**. Пропущенная существующая проверка относится к сгенерированному оформлению установщика.
- Добавлено **15** модульных/HTTP-регрессионных тестов: медленные API, ранний резерв, проигравший subprocess, ошибка резерва при рабочем прямом пути, повышение hover-запроса, сброс сессии и защита от устаревшего кэша.
- `node scripts/check-structure.cjs`: успешно.
- Chromium: новый тест сравнения старого и нового поведения, существующие direct-stream, session-stream, adaptive-stream, audio-engine и background проверки прошли. Проверены реальные WAV-байты через локальный HTTP-прокси, декодер, AudioContext/анализатор, пауза и перемотка.
- Локальный сценарий с искусственной задержкой player API **3500 мс** и имитацией резервного subprocess **20 мс**: от запуска до события `playing` **3566 мс → 1546 мс**. Это демонстрация устранения последовательного ожидания, **не замер скорости YouTube или Windows**.
- Для полного регрессионного прогона в изолированное тестовое окружение установлены уже заявленные проектом `three@0.180.0` и `music-metadata@11.16.1`; lock-файлы и версии зависимостей не менялись. Их установка устранила первоначальные ошибки тестовой среды.

Отчёты: `app/tests/results/startup-local.json` и `app/tests/results/startup-fix/`.
Исторические approved-манифесты не переписаны: добавлен отдельный проверяемый inverse-слой только для исторических контрольных тестов. Живые HTTP-тесты используют изменённый код; отдельный контроль сравнения использует точный исходный AdaptiveAudio.

## Запуск и сборка

Из корня проекта, в подходящем окружении Node/Electron:

```sh
npm ci
npm start
```

Быстрая проверка исправления без запуска Electron:

```sh
cd app
npm run test:startup
```

Полный прогон из корня: `npm test`. Сборка Windows использует существующий `npm run dist` и прежние требования к нативным инструментам проекта. Готовый EXE здесь не собирался и не тестировался.

## Ограничения

Не проверены живой YouTube, реальные аккаунты, Windows subprocess termination и реальное звуковое устройство. Тестовый subprocess синтетический; его отмена не доказывает поведение всех дочерних процессов на Windows.

Это не обещание мгновенного запуска: сам резервный загрузчик, сеть/CDN и сопоставление Spotify/Apple Music с YouTube могут оставаться медленными. Последовательный поиск соответствий каталога, сетевые таймауты `account.api()`, дополнительные загрузки анализа ритма и полная отмена всех старых активных запросов при ручном переключении в этом узком исправлении не менялись.

Если после сборки остаётся большая задержка, нужен встроенный Audio Log для конкретного случая: пять быстрых правых кликов по логотипу Pulse → Audio / Звук → Start recording → включить проблемные треки → Stop recording → Save JSON. Не присылайте cookies или токены.

## Применение архива изменений

Малый архив `Pulse-1.0.3-StartupFix-changes.zip` предназначен **только** для распаковки поверх исходного первого архива AdaptiveAudio с заменой совпадающих файлов. Для AudioBackground он не подходит. Полный архив исходников уже содержит изменения и не требует отдельного наложения малого архива.
