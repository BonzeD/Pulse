# Audio diagnostics v2 — StartupFix-AudioDiagnostics2

Это диагностическое обновление предыдущей версии StartupFix, не новый фикс скорости запуска. Правила выбора аудио, качество, тайм-ауты, повторы, очереди и момент выдачи URL не менялись. Подготовка первого плана при переключении трека намеренно не исправлялась — теперь её проще увидеть в логе.

## Что добавлено

- `backup-queue`: ожидание существующей очереди резервного загрузчика.
- `backup-runtime`, `backup-health`, `backup-download`: подготовка загрузчика, выбор bundled/updated/single-exe/path, проверка запуска и промах/попадание health-cache. Версия yt-dlp берётся из уже существующего файла версии, если доступна; дополнительный процесс `--version` не запускается.
- `backup-process`, `backup-spawned`, `backup-output`, `backup-url`: длительность процесса, успешный spawn, первый stdout/stderr, первое получение URL, exit code и сигнал завершения. Сам URL и текст stdout/stderr НЕ экспортируются. По разнице времён можно отличить задержку до первой ссылки от ожидания закрытия процесса.
- `client-policy`, `resolve-path`, `prefetch-policy`: разрешён ли прямой клиент, причины пропуска/cooldown, выбор прямого/резервного пути, ограничения hover/next-prefetch.
- `resolve-shared`, `parentOperation`, `sharedOperation`: какая операция обслуживает повторные запросы; связь resolve, backup, probe и upstream.
- `load-switch`, `previousTrack`: смена выбора с анонимными метками треков. Операции старого трека, продолжающиеся после переключения, остаются видны под старой меткой.
- `purpose`: `analysis` для AutoSync, `playback` для запросов media element, `unknown` если источник не определён. Числовые границы Range, Content-Length, размер диапазона/всего ресурса, номер попытки upstream и полученные байты помогают отличить анализ от воспроизведения.
- `media-error.code`: числовая ошибка встроенного YouTube-плеера, когда её передаёт API.
- `reason`: безопасные категории ошибок: HTTP 403, rate limit, bot check, login/age restrictions, DNS/TLS/connection/timeout, недоступность видео, JS/extractor/runtime/spawn. Это классификация, а не гарантированный окончательный диагноз; неизвестные ошибки остаются `unknown`.

## Формат и приватность

`pulseAudioLog: 1` сохранён для совместимости; добавлены `diagnosticsVersion: 2` и `build: "StartupFix-AudioDiagnostics2"`.

Запись включается только вручную. В памяти хранится кольцевой буфер до 1000 событий и до 256000 байт JSON самих событий; полный JSON немного больше из-за контейнера. Максимальная длительность записи — 10 минут; старые события вытесняются, число указано в `dropped`.

Экспорт допускает только заранее заданные категории, ограниченные числа и анонимные T-метки. Нет названий треков, ID треков, URL, файловых путей, cookies, токенов и сырых текстов ошибок/вывода процесса. `authCookies` — только булев признак передачи cookies, без их содержимого. Состояние входа в аккаунт не менялось.

## Как собрать следующий лог

1. Закрыть старую Pulse и запустить новый portable. В окне разработчика открыть Audio / Звук и начать запись.
2. Включить проблемный трек и дождаться звука либо ошибки. Затем переключить ещё 1–2 трека; один из них можно включить повторно для проверки cache hit. Не очищать cookies или кэш ради теста.
3. Остановить запись и сохранить JSON. Проверить заголовок `diagnosticsVersion: 2`, `build: StartupFix-AudioDiagnostics2`. Прислать JSON целиком.

- `npm test`: 550 тестов, 549 passed, 0 failed, 1 skipped (необязательная проверка artwork установщика).
- Добавлено 14 тестов: подэтапы backup, URL до завершения процесса, коды/категории ошибок, анонимность и redaction, границы буфера, корреляция и перезапуск захвата, skipped/cooldown, разделение AutoSync/playback, неизменность сетевых запросов/аудиобайтов при включении записи.

- Это Linux-сборка Windows-пакета без подписи. Нативный запуск под Windows и реальные запросы YouTube здесь не проверялись.

## Исходники изменений

Архив `AudioDiagnostics2-source-changes.zip` содержит новые/заменяемые файлы относительно `Pulse-1.0.3-AdaptiveAudio-StartupFix-source.zip`, а не исходного AdaptiveAudio/AudioBackground. Распаковать поверх предыдущего StartupFix с заменой. Сборка только portable: сначала `npm ci`, затем `npm run build:media` при наличии .NET 8, затем `npx electron-builder --win portable --x64 --publish never`. `npm run dist` не использовать для portable-only: в прежнем проекте он также вызывает сборку setup.
